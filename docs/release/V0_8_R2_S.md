## 구버전 탭 격리 재현

사용자의 실제 탭이 아닌, 같은 Chromium 프로세스·컨텍스트 안에서 재현했다. R1 때 보관한 실제 구버전 HTML/JS를 최초 로드에만 응답하도록 구성했다. 원본 구버전 CSS는 보관하지 않아 레이아웃용 CSS만 현재 버전으로 대체했으며, 버전 동작 검증은 원본 구버전 JS를 사용했다. 보관 JS SHA-256: `8e26c24b3bb86a77ba5201f85a9cbb9635585807fe6afbc881c677022ff102dc`.

1. 구버전 HTML/JS 최초 로드: `v0.4-B · Demo`.
2. `#market` SPA 이동: 문서 요청 0회, 구버전 표시 유지.
3. 같은 컨텍스트의 새 탭에서 실제 서버 로드: `v0.8 · UI 후보`. 기존 탭은 여전히 구버전.
4. 기존 탭의 정상 `page.reload()`: `v0.8 · UI 후보`와 지표 버튼 확인. 브라우저 재시작·사이트 데이터 삭제 없음.

배포는 이미 실행 중인 SPA의 JS를 교체하지 않는다. hash 메뉴 이동도 HTML을 다시 받지 않는다. 따라서 서버가 최신이어도 열린 탭은 이전 UI로 남을 수 있다. **이 동작을 확인했지만, 사용자 탭의 실제 URL·네트워크 자산·HTTP 캐시는 직접 확인하지 못했으므로 그 탭의 원인을 확정하지 않는다.**

## 사용자 해결 절차·범위

Windows Chrome에서 입력 중인 내용을 정리한 뒤 현재 탭에서 **F5 또는 Ctrl+R**로 정상 새로고침한다. 여전히 구버전이면 **Ctrl+Shift+R 또는 Ctrl+F5**로 강력 새로고침한다. 새 탭이나 시크릿 창에서 `https://pchjesus.github.io/us-stock-lab/?verify=v08-r2-s#home`을 열어 비교할 수도 있다. PC에서는 `v0.8 · UI 후보`와 주요 시장 지표 버튼이 기준이다.

브라우저 재시작이나 사이트 데이터·localStorage 삭제는 필요하지 않다. 로컬 가상계좌 보존을 위해 데이터 삭제를 해결 절차에 포함하지 않는다. 이후에도 이전 UI면 실제 탭의 주소와 Network의 HTML/JS 경로를 확인해야 한다.

이번 변경은 이 문서·DEVLOG뿐이며 개발 브랜치에만 기록한다. main·Pages·운영 DB/Auth/Cron·금융 migration·RPC/RLS는 변경하지 않았다. 실제 주문·계정 생성 없음. 전체 build/212개 회귀·무거운 금융 테스트는 코드 변경이 없어 재실행하지 않고 기존 결과를 재사용했다.

현재 세션의 상세 근거는 로컬 `work/v08-r2-s/http.json`, `browser.json`, `verify.mjs`에 보관했다. 화면 2장은 로컬에만 두고 이미지 커밋은 하지 않는다. `git diff --check`로 문서 변경을 검사한다.
