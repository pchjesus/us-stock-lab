## 검증 구분과 보존

- 기준 결함 재현은 격리 트랜잭션 끝에 rollback, 과거 데이터 수정 없음. 정책 v1(예시10bp/최소0) 추가는 미래 주문에만 적용, 이전 주문 fee_policy_version은 NULL(기존 자기신고)로 남긴다.
- 004→005→006 populated DB에 007 실패를 주입: DDL/함수 변경 rollback, 기존 RPC 정의 보존. 정상 upgrade 후 orders/ledger/credits/positions/accounts의 금융 필드/tax history 해시 동일. clean install은 별도 DB 및 실제 pg_cron fixture에서 확인.
- 구형 금융/RLS/동시성 검사 원본을 006에서 모두 실행하고, 007에서는 v2 정확값 계산·과매수/정책/권한/CAS 검사 추가. 과거 검증을 삭제하거나 정책 조작 방지 검사를 우회하는 공개 test API는 없다. 테스트 clock은 disposable stock_test에서만 교체.
- 2독립 기기(독립 SQL 세션)가 같은 B revision으로 주문할 때1개 체결/1개 CAS 거절, A의 동시 주문은 독립. A/B/C 및 정수 경계 계좌의 실제 SQL snapshot을 배포 클라이언트 decodeManual로 재생. 별도 integration 테스트는 `playwright.finance.config.ts`, test-server.py가 synthetic snapshot을 임시 전달하고 삭제한다.
- 위 검증은 독립 연결로 기기를 모델링한 검사이며 실제 휴대전화·운영 Supabase Auth 검사는 아니다. 실제 인증 기기 smoke는 운영 전 게이트에 남긴다.
- 주문 confirm 직전 서버 CAS 실패는 pending 해제·입력 보존·최신 계좌 재조회, 불확실한 결과는 같은 ID만 재확인. 수수료 입력은 서버 정책 read-only, 정책/ledger snapshot 변조 거절. 원본 오류/로그아웃/A-B 전환/저장 실패 기존 검사 유지.
- 세금 외부 손익은 기본공제 전, 사용공제는 해당 외부 순이익 이내. `max(합산순익-2,500,000,0)`과 모든 허용 공제 배분의 세액 일치/공제 중복 없음 검사. 매수비용 원가 포함/매도비용1회, 15% 배당세와 원화 양도세 분리. 공식 법률·명세 미확정 사항은 E절 그대로 잠정 표시.
- 모든 public SECURITY DEFINER의 anon/authenticated 실행권한/빈 search_path, 내부 private helper 접근 회수, NULL auth.uid 거절을 catalog+실행 검사. ordinary 사용자 direct 금융/정책/배당/세금 쓰기 불가. 관리자 역할은 DB allowlist, user_metadata 무시.
- 거래총액/수수료/원가/누적액은 안전 정수 제한, 곱셈/비율/실현손익 중간 차감은 BigInt 또는 SQL numeric. 수수료·부분매도 원가·배당 gross와 15%세금을 각각 센트 half-up. FX는 6자리 고정소수점 후 원 단위 half-up, 국세/지방세 각각 원 단위 반올림. 법정 신고 절사/정책을 인증하지 않으며 잠정 안내 유지.

## 잠금 순서 / 잔여 한계

- 계좌 초기화/주문/정책변경은 자기 account row를 먼저 잠금. 신규 주문은 잠금 후 CAS+활성 정책 확인 → 기존 시장시간 gate/math → 같은 트랜잭션 원장/정책 참조. 배당은 scheduler advisory lock → 운영 control shared → event → account 순서. 주문 snapshot은 event를 읽기만 하고 event row lock을 취하지 않으므로 역방향 account→event 잠금 없음. 관리자는 control→event(중단) 또는 event(공시)만 잠금, account 잠금 없음. 세금 저장은 account→자기 tax revision, 금융 원장은 미변경.
- private Cron owner 및 DB owner는 신뢰된 운영자다. 같은 SQL owner가 원장을 직접 변조하는 것까지 방지한다고 주장하지 않는다. 오류 격리/재시도/중단·보정 검토는 D 정책 유지. 기지급 공시 수정은 review/audit이며 자동 역분개 없음.
- 세액은 교육용 잠정치. 일반 국세20%/지방2%·FIFO/평균·원화 환산/한국 귀속연도·국내 통산/거주·증여 예외·완전 DTCC 일정의 모든 법적 적용은 공인 신고 근거가 아니다. E 기록의 공식 확인 범위/미확정 범위를 유지. 수기 가격·수기 FX 증빙의 진위를 서버가 보증하지 않는다.
- 기기별 입력/평가가격/읽음 상태는 로컬. 서버 금융/지급 이력은 로그인 후 복원된다. 로컬 저장소는 기기 사용자에 대한 보안 경계가 아니며 민감정보·실계좌 입력 금지.
- 구조 판단: 전면 리팩터링 보류. 재발 위험은 수기 RPC의 입력/정책 경계와 비동기 화면 상태에 집중되어 wrapper·revision·국소 타이밍 수정으로 제어했다. 라이브러리/불필요한 계층 추가와 paper_* 금융 변경 없음.

## 운영 전환 계획 / 복구

1. 사용자 승인: 적용할 정확 SHA/004~007 순서, 초기 예시 정책10bp/0 및 변경 관리자, 배당 관리자, 세금 잠정 범위/이용자 안내, 공개 정적 사이트 접근성을 검토. 저장소 visibility 변경 없음.
2. 권한/설정: 기존 Supabase 프로젝트만 사용. public VITE URL/publishable key 외 관리·service_role/DB credential은 trusted operator 환경에만 보관. 새 프론트 비밀키 불필요. cron은 DB owner 내부 실행이므로 HTTP 비밀키 불필요. 정책 관리자와 배당 관리자는 별도 private allowlist이며 자동 승격/브라우저 플래그 금지.
