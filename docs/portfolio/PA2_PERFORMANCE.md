# PA2 수익·위험 분석 계약

PA1의 계좌 구성·집중도·가상 비중 실험은 유지한다. CSV는 별도 메모리 자료이며 계좌·서버·localStorage에 반영하지 않는다. 사용자 계정 전환, 페이지 이탈 또는 새로고침 시 가져온 자료를 버린다. 같은 계정의 계좌 스냅샷 갱신만으로 가져온 자료를 지우지는 않는다.

## CSV

`date,currency,source,value,flow,benchmark_return,risk_free_return`

날짜 YYYY-MM-DD, USD 또는 KRW의 단일 통화, user(실제라고 사용자 신고/미검증) 또는 synthetic(합성)의 단일 출처. 평가액과 외부 현금흐름은 소수 2자리까지이며 정수 최소단위로 검증한다. CSV 숫자에 천 단위 쉼표와 인용부호를 지원하지 않는다. 2~10,000행·2MB 제한. 중복·역순·잘못된 날짜·필수값 누락·혼합 통화/출처·초과 범위는 거부한다.

첫 행은 시작 평가액 >0, flow=0, 선택 수익률은 빈칸이다. 이후 flow는 해당 관측일 말 입금 양수/출금 음수이고 value는 흐름 반영 후 평가액이다. 관측 사이 흐름이 있으면 그 시점의 평가값으로 분할해야 하며, 장중 흐름을 임의로 일말로 바꾸지 않는다. 내부 매매와 계좌 내 배당 재투자는 외부 흐름이 아니다. 선택 수익률은 직전 날짜부터 현재 날짜까지 같은 통화·출처의 총수익률 소수이며 연 이율을 그대로 입력하지 않는다. 각 열의 기간·통화·자료 종류 정합성은 사용자 신고로서 외부 검증 완료로 주장하지 않는다.

## 계산

- 구간 수익률: `(종료 평가액−일말 흐름)/직전 평가액−1`. TWR은 구간 `(1+r)`의 곱 −1. 시작 이후 평가액 0으로 다음 구간 분모가 0이면 미제공.
- CAGR: 외부 흐름이 전혀 없을 때 `(종료/시작)^(365/일수)−1`. 짧은 기간 연환산은 불안정하다.
- XIRR: 시작 투자는 음수, 입금은 음수·출금은 양수, 마지막 평가액은 회수로 합쳐 실제 일수/365 할인한다. log(1+r) 구간 −20~20에서 이분법·잔차 검증. 부호 변화가 정확히 한 번인 현금흐름만 계산해 복수 해 가능성을 보수적으로 배제한다. 경계값 −100% 또는 탐색 범위 밖은 미제공.
- MDD: 단위화 TWR 지수의 누적 고점 대비 최저 하락률. 금액 곡선으로 출금 효과를 위험으로 오인하지 않는다.
- Volatility: 표본 표준편차 × sqrt(365/구간일수). Sharpe는 구간 초과수익률 평균/표본 초과수익률 표준편차 × sqrt(연 구간수). Sortino는 같은 평균/모든 구간을 분모로 하는 하방 RMS × sqrt(연 구간수); 목표는 해당 구간 RF다.
- Beta는 RF 차감 없는 시장모형의 표본 공분산/벤치마크 분산, Correlation은 표본 상관. Tracking Error는 두 수익률 차이의 표본 표준편차 연환산, Information Ratio는 차이 평균/그 표준편차 연환산.

위험·비교 지표는 최소 2개 구간과 같은 간격을 요구한다. 거래일 달력이나 월말 간격을 추정해 252·12를 자동 적용하지 않는다. 불규칙한 자료에서는 연환산 위험·비교 지표가 미제공이지만 TWR, XIRR, MDD 및 흐름 없는 CAGR은 가능하다. 선택 자료가 불완전하거나 분산·추적오차·하방편차가 0이면 각 사유를 표시한다. 금액 파싱은 BigInt, 수익률·통계는 Number이며 유한값 여부를 확인한다.

성장 곡선의 누적 순납입금은 시작 평가액+외부 순입금이고 음수가 될 수 있다. 성장 지수·Drawdown은 흐름 조정 수익률을 사용한다. 샘플은 전부 합성이고 앱의 합성 계좌와도 합치지 않는다.

## 독립 기준과 검증

2개 연간 수익률 +10%, −5%의 TWR은 4.5%, MDD −5%, 변동성 15%/sqrt(2). 같은 구간의 벤치마크 +8%, −2%에서 beta 1.5, correlation 1, 추적오차 5%/sqrt(2). RF 3%,3%로 Sharpe·Sortino를 별도 수식 기준과 대조한다. 시작 1,000 → 일말 500 입금 후 1,600 → 1,760은 TWR 21%, XIRR 10%이며 CAGR은 미제공이다. 검증 결과는 DEVLOG를 참고한다.


최종 검증: build/TypeScript PASS, 전체 UI 392건 및 Auth 54건 PASS. 마지막 모바일 축·정확값 표시 변경 후 핵심 14건 PASS. Excel의 비정기 현금흐름 예시(2008-01-01 −10,000, 2008-03-01 +2,750, 2008-10-30 +4,250, 2009-02-15 +3,250, 2009-04-01 +2,750)의 XIRR 0.373362535와도 대조했다. 운영 DB/API·실기기는 검증하지 않았다. Release/UX0 전용 회귀는 이번 단계에서 실행하지 않았다.
