# AC1-A1 · 가상계좌 생애주기 서버 계약 (개발 전용)

상태: **격리 PostgreSQL 테스트 PASS / 운영 Supabase 미적용 / UI 미연결 / main 미병합**

## 현재 제약과 변경 이유

기존 운영 스키마는 `paper_accounts.user_id`의 단일 UNIQUE 제약을 사용한다. `paper_snapshot()`은 `paper_account_id()`를 통해 첫 계좌를 자동 생성한다. 또한 기존 비로그인 로컬 계좌의 초기화는 거래 이력을 지우므로 "계좌 종료 후 새 계좌 개설"과 동일하지 않다.

AC1의 목적은 사용자 인증 계정의 삭제가 아니라, **가상 투자계좌의 종료 및 재개설**이다. 이력은 별도 계좌 ID에 보존한다. 이 단계에서는 운영 스키마·데이터 및 브라우저 앱을 변경하지 않는다.

## 새 서버 계약 (migration 008)

- `paper_accounts.status`: `active` 또는 `closed`; 종료 시각 `closed_at`. 사용자당 활성 계좌 1개를 부분 UNIQUE 인덱스로 보장한다.
- `paper_account_id()`: 활성 계좌가 있으면 재사용한다. 계좌 이력이 전혀 없는 첫 방문에서만 기존 방식대로 자동 생성한다. 종료 계좌만 있다면 `account_closed`를 반환하며 자동 재생성하지 않는다.
- `paper_open_account()`: 활성 계좌가 없는 사용자만 명시적으로 신규 계좌를 개설한다. 신규 UUID, `10000000`센트 가상자금 및 독립 최초원장을 생성한다. 기존 이력은 복제·삭제하지 않는다.
- `paper_close_account(expected_id)`: 현재 활성 계좌의 UUID를 확인하고 종료한다. 이미 종료된 같은 계좌에 대한 반복 요청은 안전하게 완료 상태를 반환하며, 이후 새로 개설된 계좌를 이전 요청으로 종료하지 못한다.
- `paper_accounts_overview()`: 읽기 전용, 자동 개설 없는 활성/종료 계좌 및 계좌별 요약 목록.
- `paper_archived_snapshot(id)`: 현재 인증 사용자 소유의 종료된 계좌만 거래·원장·보유정보를 읽기 전용으로 제공한다.
- `paper_order()`: 기존 시장 시간·멱등성·원장 계산을 유지하면서, 이전 계좌의 `client_request_id`가 새 활성 계좌로 재실행되는 경우 `idempotency_conflict`로 거절한다.
- 스키마 변경·운영 인증·서버 잔고 및 주문 분리는 모두 **격리 데이터베이스에만 적용**했다. `manual_*` 계좌 및 004~007 운영 미적용 상태는 변함없다.

## 향후 UI 전환 시 필수 조정

1. 현재 서버 `serverSnapshot()`은 활성 계좌만 있다고 가정한다. `account_closed`가 나면 에러 대신 "종료됨 / 이전 계좌 보기 / 새 계좌 개설" 상태를 보여주도록 상태 모델을 확장한다.
2. 계좌 종료 화면에서 **가상계좌 UUID·현재 주문 보류 여부·확인 문구**를 확인한다. 보류/체결 불확실 주문은 같은 주문 ID로 우선 확정한다.
3. 신규 계좌 개설 이후에도 과거 계좌를 읽기 전용으로 탐색할 수 있어야 한다. 현재 `useAccount()` 및 `AccountView`가 반환하는 계좌 ID와 데이터 캐시를 계좌별로 분리한다.
4. 비로그인 로컬 데모의 `resetAccount()`는 이력 삭제형이므로, 별도 세대별 아카이브 계약을 설계하기 전에는 AC1의 "종료" 버튼으로 재사용하지 않는다. 로그인 여부에 따른 UX를 구분한다.
5. 상태 변경 직전 다른 탭·기기에서 갱신된 계좌 확인, 주문경쟁, 같은 계좌 재개설 중복 시도, 신규 재입금 1회만 지급하는 원장 불변성을 테스트한다.
6. 앱 UI 구현·운영 DB migration 008 적용·feature flag ON·실계정 테스트·Pages 배포는 **각각 별도 승인 및 별도 검증**이 필요하다.

## 실제 검증 결과

[격리 PostgreSQL 성공 실행 #44091143613](https://github.com/pchjesus/us-stock-lab/actions/runs/44091143613): 서로 다른 임시 데이터베이스 두 개로 기존 001~003 서버 회귀와 신규 008 계좌 생애주기 SQL을 분리 실행했다.

- **기존 서버:** 매수·매도·멱등성·다중사용자 격리·원장 롤백 PASS.
- **AC1:** 최초 계좌 자동 생성, 종료 후 자동 재개설 차단, 명시적 재개설, 이력 보존, 과거 주문 ID 재실행 차단, 오래된 종료 요청 차단, 다른 사용자 계좌 조회/종료 RLS, 익명 RPC 제한 및 원장 초기자금 1회 지급 PASS.
- 임시 QA workflow는 성공 후 제거했다.
- 동시성 부하·운영 Supabase 사전 백업/복구·실기기·실제 로그인 상태·브라우저의 AC1 UI는 **NOT VERIFIED**. 이 파일을 근거로 운영 migration을 실행해서는 안 된다.

## 설계 개편과의 관계

계좌 기능의 데이터 계약은 먼저 확보하되, 새로운 계좌 관리 화면은 **기능 보존형 UI 전면 재설계의 프로토타입**에서 설계한다. 기존 화면에 임시 버튼을 덧붙였다가 삭제하는 중복 개발을 피한다.
