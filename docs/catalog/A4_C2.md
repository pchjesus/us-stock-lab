## 출처와 이용 조건

SEC [CIK·회사명·티커·거래소 매핑](https://www.sec.gov/files/company_tickers_exchange.json)은 발행인 매핑 후보이며 전체 현재 상장증권, 증권 유형, 활성 상장 여부를 증명하지 않는다. CIK는 발행인 식별자여서 한 CIK에 복수 클래스가 있을 수 있다. [SEC Fair Access](https://www.sec.gov/about/developer-resources) 및 [EDGAR 접근 안내](https://www.sec.gov/search-filings/edgar-search-assistance/accessing-edgar-data)의 신원 식별과 전체 요청률 제한을 따라야 한다. 이 구현의 간격 제한은 **이 저장소의 단일 스냅샷 루트**에 한정되므로, 다른 프로세스·다른 머신·같은 공인 IP에서 발생하는 SEC 요청까지 합산하여 사용자가 관리해야 한다. 자동 정기 수집은 등록하지 않았다.

[Nasdaq Symbol Directory 정의](https://www.nasdaqtrader.com/Trader.aspx?id=SymbolDirDefs)를 2026-11-04에 확인했다. 파일은 하루 중 주기적으로 갱신되며 마지막 `File Creation Time`은 파일 생성시각이다. Nasdaq 상장과 타 거래소 상장 파일이 분리되고 `Test Issue`는 Y/N 시험 종목 여부다. 타 거래소 파일의 `Exchange`는 상장시장 코드, `ETF`는 Y/N ETF 여부다. 이름에 유형·클래스 문구가 있을 수 있으나 이름만으로 유형을 판정하지 않는다. 갱신시각은 개별 증권의 상장 이력이나 법적 증거를 대체하지 않는다.

NasdaqTrader의 [저작권·면책 조건](https://www.nasdaqtrader.com/Trader.aspx?id=CopyDisclaimMain)은 사이트 콘텐츠의 복제·배포 등에 원칙적으로 사전 서면 동의를 요구하고 제한적인 예외를 명시한다. 이 문구만으로 별도 디렉터리 데이터 파일의 구체적인 라이선스·공개 재배포 권한을 확정할 수 없다. Nasdaq 데이터 파일은 요청·복제·통합하지 않았으며 보조 어댑터도 활성화하지 않았다. 별도 약관과 허가 확인 후에만 재검토한다. SEC 자료 역시 이 구현의 해시만으로 공개 재배포 권한이 확정되는 것은 아니다. 실제 원본과 큰 스냅샷을 공개 저장소에 넣지 않는다.

## 수집 명령과 안전 경계

Node 24의 환경 프록시 지원을 사용한다. `SEC_USER_AGENT`에는 **실제로 연락 가능한 담당자/조직과 이메일**을 사용자가 직접 설정해야 한다. 값은 코드·문서·로그·스냅샷에 넣지 않는다. 예시/가짜 연락처로 실제 요청하지 않는다. 터미널의 숨김 입력 등 로컬 환경에 맞는 안전한 방법으로 값을 설정한 후 다음을 실행한다.

```sh
npm run catalog:collect
```

식별 정보가 없거나 명백한 예시/invalid 형식, 예약된 `.test`·`.example`·`.invalid` 및 example.com/org/net 주소이면 설정 방법을 알리고 네트워크 요청 전에 실패한다. 형식 검사는 연락처의 실제 소유·수신 가능성을 증명하지 않으며, 실제 식별 정보의 진위는 실행자의 책임이다. 테스트에 쓰는 가상 연락처는 주입된 가짜 fetch에서만 사용한다.

CLI는 정확히 `https://www.sec.gov/files/company_tickers_exchange.json`만 요청한다. 모든 리다이렉트는 허용 호스트 여부와 관계없이 거부한다. 요청 전 루트별 잠금을 획득하고 이전 요청과 최소2초 간격을 유지한다. 5xx만 최대3회 시도하며 403/429와 `Retry-After`가 있는 5xx는 즉시 중단한다. 각 요청은15초 제한, 원본20MiB 상한, JSON content-type·identity encoding·유효한 Content-Length와 전체 바이트 수·UTF-8·JSON·정확한 SEC fields/schema를 검사한다. 중단·초과·오류·빈 자료는 저장하지 않는다. 본문 수신 완료 후 실제 UTC 시각을 초 단위 `checkedAt`으로 기록한다. SEC 파일에 명시된 원본 기준일이 없으므로 `sourceAsOf`는 항상 null이며 응답 시각이나 Last-Modified로 대신하지 않는다.

현재 CLI는 입력 행이나 충돌/중복을 제외하고 남은 유효 후보가 각각1,000개 미만이면 불완전 자료로 실패한다. 이는 공식 최소치가 아닌 보수적인 이상 징후 차단값이다. 수신된 1,000개 이상의 유효 후보도 완전한 SEC 목록임을 증명하지 못하며 실제 형식 변화나 압축 응답은 명시적으로 실패해 검토해야 한다. 서버 차단·타임아웃 시 우회하지 않는다.

## 정규화·스냅샷·로더

기존 `normalizeSec`을 재사용한다. 심볼 구두점을 유지하며 거래소+정규화 심볼을 후보 ID로 사용한다. 같은 CIK의 다른 클래스와 거래소가 다른 같은 심볼은 병합하지 않는다. 같은 ID에서 정규화 결과가 다르면 해당 그룹 전체를 보류한다. A4-C1과 동일하게 중복 여부는 trim/심볼 대문자화 **후 정규화된 전체 행**의 동등성으로 결정한다. 따라서 입력 심볼의 대소문자만 다르고 정규화 결과가 완전히 같으면 중복이다. 원본 바이트와 0기반 행 번호를 보존하므로 원시 표기의 차이를 추적할 수 있다. 이 동작은 A4-C1 fixture의 `DUP`/`dup` 계약을 유지한다.

손상된 행은 `invalid-row-shape`, `invalid-cik`, `invalid-name`, `invalid-symbol`, `invalid-exchange` 등의 사유로 기록한다. 중복과 충돌도 각각 행 번호와 후보 ID를 기록한다. 분류는 전부 `unknown`, 상장 상태는 `unverified`, 거래는 `tradeEligible: false`다. 기존8개 거래 종목과 후보를 자동 병합하지 않는다. 심볼 재사용·상장폐지·합병·클래스 변경·별도 증권 식별자는 미확인이다. 재정의된 exchange ID는 영구 식별자가 아니다.

`work/catalog-snapshots/`는 Git 제외 대상이다. 각 성공 수집은 UTC 시각+원본 SHA-256으로 별도 디렉터리를 독점 생성한다. `raw.json`은 수신 원본 바이트, `catalog.json`은 결정론적 후보·counts·issues, 마지막으로 작성되는 `manifest.json`은 commit marker다. 원본 URL·수집시각·원본 기준일 null·SHA-256·바이트 수·행/정규화/제외/중복/충돌 건수·정규화 SHA-256·검증 상태를 기록한다. 권한은 가능한 환경에서 디렉터리0700/파일0600으로 설정한다. 기존 경로를 덮어쓰거나 자동 삭제하지 않는다.

읽기 전용 Node 로더 `loadSecSnapshot(directory)`는 manifest·원본·정규화 파일의 해시/크기/메타데이터를 검사하고 원본을 다시 정규화해 결과 바이트와 건수를 비교한다. commit marker가 없는 부분 디렉터리, 오류 응답, 변조·불일치는 거부한다. 동일 입력과 메타데이터는 같은 결과를 생성한다. SHA-256은 바이트 일치성을 확인할 뿐, 로컬 공격자가 원본·결과·manifest를 함께 바꾼 경우 출처 진위나 법적 권리를 증명하는 서명이 아니다. 별도의 신뢰할 수 있는 해시/서명·출처 검토가 필요하다. 파일 시스템에 fsync 내구성 보장은 추가하지 않았으며 전원 장애 시 미완료 최신 스냅샷은 로더가 거부한다.

잠금은 동시 요청을 차단한다. 프로세스 강제 종료로 `.sec-ingest.lock`이 남으면 자동 해제하지 않는다. 실행 중인 수집이 없음을 확인한 뒤에만 사람이 stale lock을 정리한다. 실패한 새 수집은 이전 스냅샷을 수정하지 않는다. 로더는 A5 준비용 서버/오프라인 계약이며, 이번에는 브라우저 번들이나 검색 UI에 자료를 연결하지 않는다.

## 운영과 A5

금융 계산·원장·합성 가격/캔들·8종목·Auth/계좌 격리·수기/배당/세금·RPC/RLS/SQL·migration004~007·홈/학습·기업/ETF 상세는 변경하지 않는다. Pages는 수동 workflow이고 finance/market push는 과거 전용 브랜치만 대상이다. A4-C2 개발 브랜치만 `[skip ci]`로 커밋·push하며 main 병합·배포·운영 설정·정기 수집을 실행하지 않는다.

로컬 fixture 기반 A5 로더/화면 개발은 가능하다. **실제 데이터 기반 검색의 공개 통합은 아직 준비되지 않았다.** 실제 SEC 수집과 형식/건수 확인, 권리·최신성·증권 유형/상장 상태·식별자 충돌 검토가 필요하다. 신규 후보의 거래 권한이나 실제 시세 연결은 후속 승인 범위이며, 이 개발 결과는 운영 배포 승인이 아니다.
